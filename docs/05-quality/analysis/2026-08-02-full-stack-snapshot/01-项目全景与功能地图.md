# 项目全景与功能地图

## 1. 产品是什么

“AI 知识导航”把四类需求放在一个网站里：

1. 公开学习内容：学习路线、节点、材料、章节、关系和下一步。
2. AI 工具目录：分类、检索、最新工具和预设工作流。
3. 用户空间：身份、偏好、学习状态、收藏、工作流资产和隐私生命周期。
4. 站内 Agent：围绕上述站内事实回答问题、导航、推荐工具、生成学习计划或工作流草案。

它不是一个通用互联网搜索 Agent。答案被设计为只基于站内内容，并通过站内安全链接把用户带回学习、工具或设置页面。

## 2. 用户可见页面

| 页面 | 干净路由 | 入口文件 | 主要职责 |
| --- | --- | --- | --- |
| 首页 | `/` | `frontend/index.html` | 内容入口、全站搜索、导航 |
| 学习路线 | `/learn` | `frontend/learn.html` | 路线图、领域、资源 |
| 学习节点 | `/learn/{slug}` | `frontend/learn-node.html` | 材料、章节、关系、进度、收藏 |
| 工具目录 | `/tools` | `frontend/tools.html` | 分类、搜索、最新、工作流 |
| 完整助手 | `/assistant` | `frontend/assistant.html` | 对话、引用、会话、工作流保存 |
| 用户空间 | `/settings` | `frontend/settings.html` | 账号、资料、偏好、资产、隐私 |

旧的 `.html` 地址由平台路由以 308 重定向到干净路由。`learn-node.html?slug=...` 会转换为 `/learn/{slug}`。

当前工作树还包含 2026-08-02 新增的快捷助手悬浮窗：

- 只在首页、学习和工具页面出现；
- 原生 UI，不使用 iframe；
- 动态复用 `assistant-page.js`；
- 支持拖动、固定 7:12 比例缩放、会话管理和跳转完整助手页；
- 位置、尺寸和当前会话只保存在当前标签页 `sessionStorage`。

## 3. 核心功能分区

### 3.1 Learning

Learning 负责公共知识事实：

- 6 个难度等级
- 5 个知识领域
- 16 个路线节点
- 7 条路线边
- 16 份主学习材料
- 64 个材料章节
- 88 条节点补充链接
- 标签、领域映射、推荐下一节点和语义关系

它不保存用户进度。公共 GET 即使 Users 或 Agent 不可用也应继续工作。

### 3.2 Tools

Tools 是工具目录单一事实源：

- 144 条工具记录
- 9 个分类
- 37 个子分类
- 138 个展示位
- 12 个最新工具槽位
- 3 个公共工作流
- 11 个工作流与工具关联

前端不再维护一份与数据库竞争的完整工具事实副本。Agent 通过 Tools service 搜索，不直接查 `ai_tools`。

### 3.3 Users

Users 是最大的领域，包含：

- 注册、登录、刷新、退出和密码恢复发送端边界
- PBKDF2 密码、短 Access Token、HttpOnly Refresh Cookie 与轮换
- RBAC 和资源 ownership
- 账号、资料、头像、偏好和设备会话
- 节点/章节进度、活动、最近阅读、继续学习和收藏
- 用户保存的工作流及步骤
- 同意、导出、注销、恢复和最终匿名化
- 审计、命令安全和脱敏可观测性
- 面向 Agent 的最小上下文 facade

### 3.4 Agent

Agent 支持五类意图：

| 意图 | 示例 | 默认读取能力 |
| --- | --- | --- |
| `qa` | “RAG 是什么” | `learning.search` + `tools.search` |
| `navigation` | “打开用户空间” | `navigation.read` |
| `tool_recommendation` | “推荐免费代码工具” | `tools.search` |
| `workflow_generation` | “论文阅读工作流” | `tools.search` + `tools.workflow` |
| `learning_plan` | “RAG 怎么学” | `learning.search` |

Agent 响应不仅有答案，还包含：

- 站内卡片
- 可验证引用
- 已执行/跳过的只读能力轨迹
- 工作流步骤
- 可编辑工作流草案
- 后续问题
- Provider、模型、提示版本和回退原因等元数据

## 4. 典型用户旅程

### 4.1 匿名学习

用户打开学习节点 → 公共 Learning API 返回内容 → 浏览器只记录真实节点访问 → 用户之后登录 → 匿名访问快照经 Users 导入命令幂等写入活动 → 不推断完成度。

### 4.2 登录学习

节点页面加载公共内容 → 独立请求 Users 学习状态 → 用户完成章节或修改节点进度 → 期望版本/幂等键校验 → Users repository 事务 → 审计或稳定冲突响应。

### 4.3 工具发现

用户选择分类或搜索 → Tools service 归一化查询并评分 → 返回工具事实与安全站内详情地址 → 官方外链仍受 URL 安全与链接治理控制。

### 4.4 Agent 问答

用户提问 → 规则意图分类 → 选择受控只读能力 → 生成结构化确定性基线 → 可选 Provider 只重写自然语言答案 → 输出守卫 → JSON 或 SSE → 可选会话落库。

### 4.5 Agent 工作流保存

Agent 生成草案 → 前端允许用户编辑标题、描述和步骤 → 用户勾选明确确认 → `POST /agent/workflows/save` + `Idempotency-Key` → Users Assets facade → 权限、事务、审计 → 个人工作流。

## 5. 项目目录职责

```text
backend/app/api/v1/routers   HTTP、鉴权依赖、DTO、错误映射
backend/app/agent            Agent 编排、Provider、会话、评测与治理
backend/app/core             配置和安全基础
backend/app/db               SQLite 初始化、迁移和连接
backend/app/learning         公共学习领域
backend/app/platform         导航、干净前端路由等平台能力
backend/app/tools            公共工具领域
backend/app/users            用户身份、状态、资产、隐私与审计
database                    schema、seed、内容、22 个增量迁移和本地库
frontend                    6 个静态入口及原生 JS/CSS
scripts                     验证、基准、备份、发布和证据生成
tests                       Python 与 Node 契约/服务测试
docs                        架构、任务、运行手册、审计和机器证据
deploy                      HTTP 测试与 HTTPS 生产覆盖层
```

## 6. 当前成熟度

### 已具备

- 清晰的模块所有权
- 字段级 DTO、严格输入校验和稳定错误码
- 顺序迁移、校验和、防漂移和备份恢复
- 公共内容与用户私有状态解耦
- Agent deterministic 回退和 Provider 边界
- SSE、会话、幂等重放、成本/并发保护
- 盲评协议和模型升级门禁
- 本地、HTTP 测试和生产覆盖层材料

### 尚未形成生产事实

- 真实 Provider 合规签收
- 真实北京 Provider 与上海服务器链路验证
- 真实取消、结束事件、用量和计费行为
- 2 vCPU / 4 GiB 生产容量与 SQLite 写锁表现
- 生产备份恢复、回滚、告警和值守
- 密码恢复真实邮件/短信发送端
- ICP 完成后的正式 HTTPS 公网切换
