# 架构与领域实现

## 1. 架构形态

项目采用小型模块化单体，而非微服务：

- 一个 FastAPI 应用；
- 同一个进程提供 API 和静态前端；
- 一个 SQLite 数据库；
- 一个迁移序列；
- 一个生产 systemd 服务；
- 当前一个 API worker；
- 仅 Provider 是外部网络依赖。

模块边界依靠 Python package、service/facade、port/repository 和测试约束，而不是内部 HTTP。

## 2. 分层规则

```text
Browser
  -> FastAPI Router
      -> Domain Service / Facade
          -> Repository / Adapter
              -> SQLite or External Provider
```

### Router

只处理：

- HTTP 方法、路径和查询参数
- 鉴权/权限依赖
- 请求/响应 DTO
- 稳定错误映射
- Request ID 和 transport 语义

### Service

处理：

- 用例编排
- 领域规则
- 幂等/并发语义
- 跨 repository 协作
- 输出领域结构

### Repository

处理：

- SQL
- 事务
- 排序、分页和索引利用
- SQLite 兼容细节

### Facade

只在真实跨领域消费处出现。例如 Agent 读取 Users Context、保存 Users Assets；它不是所有内部调用的通用包装层。

## 3. 领域所有权

| 领域 | 写入所有权 | Agent 使用方式 |
| --- | --- | --- |
| Platform/Core | 配置、导航基础、数据库装配 | `navigation.read` |
| Learning | 路线、节点、材料、章节、关系、内容治理 | 只调用 Learning service |
| Tools | 工具、分类、展示位、工作流事实 | 只调用 Tools service |
| Users | 身份、偏好、进度、收藏、资产、隐私、审计 | Context facade + Command facade |
| Agent | 编排、Provider、会话、重放、评测、治理 | 自身所有 |

共享数据库不意味着共享表。Agent 不应直接访问 Learning、Tools 或 Users 的领域表。

## 4. Platform/Core 实现

`backend/app/main.py` 是组合根：

1. lifespan 启动时调用 `initialize_database()`；
2. 安装 Users 观测、头像请求体限制、Learning 访问日志、安全响应头和 CORS；
3. 装配 common、agent、assets、auth、learning、operations、privacy、tools、user_learning、users 路由；
4. 装配干净前端路由；
5. 挂载 `/uploads` 和根静态目录。

统一安全响应头包含：

- `X-Content-Type-Options: nosniff`
- CSP，仅允许自身脚本和连接
- `Referrer-Policy`
- `X-Frame-Options: DENY`
- 禁用相机、麦克风、定位、支付、USB 等权限
- 生产 HTTPS 确认后启用 HSTS

Learning 公共 GET 额外得到：

- `X-Request-Id`
- `Server-Timing`
- `Cache-Control: public, max-age=60, stale-while-revalidate=300`
- 结构化访问日志

## 5. SQLite 与迁移

数据库层没有 ORM。当前运行库只读盘点：

- 46 张非内部表
- 22 条 `schema_migrations`
- 数据库文件约 1.45 MB

迁移机制的关键语义：

- 文件只追加，不修改已应用迁移；
- 保存迁移文件名与 SHA-256；
- 已应用文件内容漂移时启动失败；
- 使用事务和 `BEGIN IMMEDIATE`；
- SQLite 条件加列由自定义迁移指令处理；
- 发布回滚以已验证备份恢复为主，不依赖破坏性 down migration。

最近两个迁移是：

- `021_clean_page_routes.sql`：清理页面路由数据
- `022_learning_stable_uid_backfill.sql`：补齐 Learning 稳定 UID

因此仍写“20 个迁移”的 README 和部分 Agent 证据属于旧快照。

## 6. Learning 的实现

```text
schemas.py                严格 DTO 与外链约束
policies.py               可见性和领域策略
ports.py                  repository 契约
service.py                路线、详情、搜索、关系、下一节点、Agent Context
repositories/sqlite.py    Learning SQL
```

关键设计：

- 公共内容与用户状态分离；
- material/link 使用稳定 UID；
- publication、content version、quality、source trust、verified/check time 支持内容治理；
- 面向 Agent 的 `get_agent_context` 返回紧凑节点集合，而不是整库数据；
- 前端统一通过 `learning-api.js` 消费公共内容和用户状态；
- 用户状态失败不应阻止公共内容呈现。

## 7. Tools 的实现

```text
repository.py   加载分类、工具、展示位、最新槽位、公共工作流
service.py      查询归一化、扩展、评分、过滤、分页、推荐
```

Agent 的 `catalog_tools.py` 只把 Tools service 结果转换为站内安全卡片。它会保留工具官方 URL 供服务端事实使用，但 Agent 最终呈现的 `href` 是站内地址，Provider 被禁止自行生成 URL。

## 8. Users 的实现

Users 内部按职责拆分，但仍是一个领域：

```text
authentication   注册、登录、恢复发送端、速率限制
account          账号标识和联系方式
security         密码与安全资料
sessions         登录设备会话
authorization    RBAC
profile          公开资料和头像
preferences      偏好与消费者裁剪
learning_state   进度、章节、活动、最近、继续、收藏、导入
assets           用户工作流
privacy          同意、导出、注销、恢复、匿名化
audit            事件目录和审计写入
observability    脱敏指标
context          Agent 最小用户上下文
```

### 认证

- 密码：PBKDF2-HMAC-SHA256，默认 180,000 轮；
- Access Token：HMAC 签名的有界 JSON，默认 10 分钟；
- Refresh Token：随机值，数据库只存 HMAC hash；
- Refresh Token 通过 HttpOnly Cookie 轮换；
- 默认 14 天；
- 登录失败默认 5 次后锁定 15 分钟；
- 用户名、邮箱、手机号可作为登录标识。

### 用户学习状态

Learning 只提供“什么内容存在”，Users 决定“某用户做了什么”：

- 节点进度使用版本冲突控制；
- 章节完成有独立表；
- 活动采用 append-only + 幂等；
- recent/resume 是用户状态投影；
- 收藏由 Users 拥有；
- 匿名导入只接受真实浏览记录。

### 用户工作流资产

- 创建需要 `Idempotency-Key`；
- 更新、归档、恢复使用版本；
- Agent 保存仍调用同一 Assets facade；
- 模型输出不能直接成为数据库命令。

### 隐私生命周期

- 数据导出包括用户可见短/长期 Agent 对话；
- 不导出内部 request ID、来源会话 UID、Prompt、Provider 原始载荷或推理过程；
- 软删除恢复期保留会话；
- 最终匿名化时删除目标用户的 Agent 会话，消息外键级联；
- 其他用户数据保持不变。

## 9. 前端架构

前端没有框架和构建步骤。组织方式是：

```text
api.js / v2-api.js          HTTP、错误、刷新
users-api.js                Users facade
learning-api.js             Learning + Users learning adapter
page-shell.js               公共导航和页面壳
auth-local-state.js         当前标签页/内存鉴权状态
auth-ui.js                  登录 UI
assistant-page.js           完整和快捷助手共用控制器
agent-sse.js                SSE 严格解析
guest-agent-memory.js       游客 7 天浏览器会话
assistant-launcher.js       快捷悬浮窗
url-safety.js               安全站内/站外地址
```

前端重要边界：

- Access Token 只在内存中，不写 localStorage；
- Refresh Token 只在 HttpOnly Cookie；
- 游客 Agent 对话最多 10 个，每个 40 条，7 天，存 localStorage；
- 登录不会自动导入游客 Agent 对话；
- 匿名 Learning 真实访问与游客 Agent 对话是两套不同数据；
- SSE 事件类型、序号、request ID、缓冲大小均由客户端校验；
- 已开始的 SSE 不自动退回 JSON，避免重复请求和重复计费。

## 10. 部署拓扑

### 本地

`start.ps1` 提供：

- 自动解析 Python 3.11+
- 可控创建 `.venv` 和按 requirements 指纹安装依赖
- 启动 `127.0.0.1:8088`
- 仓库外 PID/日志/状态
- R 重启、S 停止、Q 退出控制窗
- 默认开启游客 Agent 和会话，真实 Provider 仍关闭

### HTTP 测试

独立 systemd/Nginx 覆盖层用于 deterministic 测试；它不是 HTTPS 生产，也不能证明真实 Provider。

### 生产准备

当前未跟踪的生产覆盖层定义：

- 域名 `starchart-ai.xyz`
- Nginx TLS 和 HTTP→HTTPS
- 应用 loopback `127.0.0.1:8003`
- systemd 用户 `starchart-ai-production`
- 数据 `/srv/starchart-ai-production`
- 代码 `/opt/starchart-ai/current`
- 严格 systemd sandbox
- Agent JSON 20 请求/分钟，burst 8
- SSE 关闭代理缓冲

生产 runbook 状态明确为 `PREPARED / NO-GO`，ICP、恢复发送端、Provider 条款、容量、监控、备份恢复和回滚仍需外部签收。
