# Git 与 HTTP 测试部署隐私审计

> 日期：2026-07-29
> 范围：项目根目录候选、待提交改动、HTTP 部署覆盖层、发布选择和 Git 历史边界
> 限制：未读取真实 `.env`，未输出账号、密码、Token、Cookie、API Key 或服务器真实地址

## 1. 结论

- **当前文件隐私**：`GO`。候选树不包含真实环境文件、运行数据库、上传内容、日志、发布归档、私钥或真实凭据。
- **deterministic HTTP 测试部署**：保持 `GO`；本次只复核代码、配置模板、发布选择和既有脱敏证据，没有重新调用服务器。
- **Git 历史隔离**：正在以干净 subtree 候选完成修正。首次根目录迁移的当前树正确，但父提交仍可访问旧父仓库的兄弟项目；因此不能把该提交视为最终独立历史。
- **生产发布**：继续 `NO-GO`。真实 Provider、HTTPS、备份恢复、回滚、容量、合规与外部签收没有因本次 Git 审计而获得验证。

## 2. 审计方法与结果

### 2.1 文件范围

- 从 Git 实际文件清单读取候选范围，不依赖手写 allowlist。
- 使用 `core.quotePath=false` 处理中文文件名，避免把 Git 的八进制转义误判为缺失路径。
- 对当前追踪文件、待提交文件和 HTTP 相关文件分别运行 `scripts/check-no-secrets.py`。
- 单独检查敏感文件后缀、真实环境文件、数据库、上传目录、备份、日志和发布归档。

最终候选预计包含 525 个追踪文件，其中 522 个可直接通过通用秘密扫描。其余 3 个文件包含
4 处故意构造的密钥形状，用于验证输出守卫和日志脱敏：

- Agent 评估攻击样例要求密钥形状输出被拒绝；
- Agent 可观测性测试要求密钥形状请求标识不进入 trace；
- HTTP 边界测试要求 Authorization 和密码不进入访问日志。

这 4 处均为无效合成字符串，不是凭据。它们保留在负向安全测试中，并由测试断言证明不会作为
可用秘密或日志内容暴露。扫描器输出只记录文件、行号和规则，不回显匹配值。

### 2.2 标识符与地址

当前候选对以下内容均为 0 命中：

- 获批服务器的真实公网和私网地址；
- 服务器实例主机名、SSH 登录串和测试账号标识；
- 本机用户名、本机绝对工作区和用户目录；
- 私钥头、真实 Bearer、Cookie、Provider Key 和敏感环境赋值。

仓库中的地址仅允许以下类别：

- loopback 和通用绑定地址，用于本地监听或明确的反例测试；
- RFC 1918 私网地址，用于限流/代理边界测试；
- RFC 5737 文档保留地址，用于不指向真实主机的测试。

SVG 路径中的小数坐标不作为 IP 地址。真实 HTTP origin 只允许通过服务器上的 root-only
环境文件注入，不写入 Git 模板、测试或文档。

### 2.3 Git 历史与仓库边界

首次迁移提交把项目文件放到了仓库根目录，但它直接继承旧父仓库提交，因此历史仍包含兄弟项目。
本次从部署修复基线提交重新执行 `git subtree split --prefix=ai-nav-fullstack`，生成干净来源提交：

```text
8470709aa44463fbcec0e46d784d4e7e2e266d7e
```

该候选根目录只有项目文件和根级 CI，不包含旧 `agent/`、`assets/`、`design/` 或旧根站点文件。
完整父仓库 bundle 保留在被忽略的 `.repo-backups/` 中；在候选验证与发布完成前不删除现有
`master`，也不把本地备份纳入 Git。

## 4. 最小修正

- 用 RFC 5737 地址替换 HTTP 运行时测试中的真实服务器 origin。
- HTTP 覆盖层测试改为拒绝硬编码 CORS URL、Windows 路径和凭据形状。
- 将文档中的本机绝对路径替换为 `<PROJECT_ROOT>`、`<PARENT_REPOSITORY_ROOT>` 和
  `<USER_HOME>`。
- 内链安全函数统一应用公共部署前缀，防止 `/StarChart-AI/` 下的相对链接逃逸到旧站根路径。
- 测试子进程保留显式隔离依赖路径，避免自定义 Python 运行时被错误判定为配置失败。
- `.gitignore` 增加 `.ci/`、`.repo-backups/`、临时 CI 输出和本地 release 目录。
