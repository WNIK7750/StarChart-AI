# HTTP 测试前端体验修复记录（2026-07-29）

## 范围与结论

本记录只覆盖 `/StarChart-AI/` HTTP 测试实例的前端体验修复，不改变账号隔离、游客本地记忆边界、确定性 Agent、外部 Provider 禁用或生产发布结论。

- 设置页：未登录访问保持在设置页，显示页内“请登录”门禁并复用既有登录框；不再跳转首页。
- 助手：HTTP 浏览器可能没有 `crypto.randomUUID()`；请求幂等 ID 改为优先使用该 API，缺失时使用非安全、非鉴权的兼容 ID。该 ID 只用于重试/replay 关联，不能作为秘密、身份或授权依据。
- 设置入口：助手页的“设置”链接在未登录时留在助手页并打开既有登录弹窗；只有已登录状态才允许进入设置页。
- 初始化：公开导航与认证 UI 的独立读取并行执行，减少页面跳转时的串行等待；不跳过认证、能力投影或 API 超时处理。

## 复验事实

在修改前，对已批准 HTTP 测试实例进行不记录响应正文的只读/确定性检查：公开首页、助手页、导航和公开能力端点返回成功；确定性游客助手端点返回成功；未携带会话访问登录助手返回未授权。该结果不等同于真实 Provider、HTTPS 或生产验收。

根因定位为浏览器表单在发送请求前直接调用 `crypto.randomUUID()`。HTTP 非安全上下文不保证提供该 API，因此异常发生在请求处理分支之外，游客和登录模式都会表现为无法提交。

后续浏览器截图还证明，HTML 与 ES module 缓存版本不一致会使“已渲染登录用户菜单”与旧模块返回的未登录结果同时出现；设置内容容器的 `hidden` 也被 `.layout` 样式覆盖，暴露了未初始化的头像替代文本。覆盖层因此对项目响应显式使用 `Cache-Control: no-cache`，并以更高优先级的 `[hidden]` 规则保证门禁与内容互斥显示。

## 验证与回滚

- 聚焦 Node 前端回归：设置门禁、Agent 前端契约、认证 UI、游客记忆、URL 安全和页面入口全部通过；另行执行 JavaScript 语法检查与 `git diff --check`。
- 发布后仅验证：未登录设置页不离开当前路径；访客助手能提交并渲染确定性回复；旧站与公开路由继续可用。登录测试不得在 HTTP 上传入真实资料。
- 最小回滚：切回上一个 `/opt/starchart-ai/current` release 软链接并重启 `starchart-ai-http-test`；不涉及迁移、测试数据库重建或 Nginx 配置变更。

## 未验证边界

本修复不验证真实 Provider、HTTPS、容量、备份恢复、回滚演练或生产签收；生产发布继续为 `NO-GO`。
