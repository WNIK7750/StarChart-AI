# ADR：Agent 阶段 1 运行拓扑与共享状态触发条件

状态：已接受

决策日期：2026-07-23

## 决策

阶段 1 保持一个 FastAPI 部署单元和一个 API worker，不引入 Redis、独立指标服务、消息队列或 Agent 微服务。

原因：

- 当前服务器为 2 vCPU、4 GiB，SQLite 仍是主数据库；
- Provider 调用是异步网络 I/O，单 worker 可承载当前全局 8 个在途调用和 32 个有限排队请求；
- 每用户并发 1、全局并发 8、排队超时和成本上限已经有离线并发测试；
- 新增共享基础设施会增加部署、备份、监控和故障恢复成本，但当前没有多实例容量证据；
- 短期会话已经使用数据库持久化，真正需要共享的只有治理账本、完成响应重放和聚合指标。

运行时必须声明：

```text
AI_NAV_API_WORKERS=1
AI_NAV_AGENT_RUNTIME_STATE_BACKEND=process_local
```

`WEB_CONCURRENCY` 可作为 worker 数的部署平台兼容输入，但 `AI_NAV_API_WORKERS` 优先。当前只实现 `process_local`；worker 数不是 1、状态后端名称未知或未实现时，应用启动失败。

## 共享状态触发条件

只有出现下列任一项并留下容量或可用性证据，才启动共享状态任务：

1. 单 worker 在目标服务器上的 CPU 或事件循环持续饱和，且减少非必要工作后仍无法满足延迟目标；
2. 全局并发 8、排队 32 的安全边界已经成为可复现的业务瓶颈；
3. 发布要求滚动升级、无中断故障切换或两个以上应用实例；
4. 成本账本、请求重放或指标必须跨进程保持一致；
5. SQLite 本身达到已经记录的并发或可靠性迁移阈值。

不能仅因“企业级”或未来可能扩容而提前引入共享服务。

当前开发机离线基线使用单进程、并发 8 和 64 次确定性请求，P95 为
262.02ms，低于 1500ms 开发门槛。结果归档于
`docs/06-evidence/agent/agent_runtime_baseline.json`。该结果不联网、不包含真实
Provider 延迟，只能与同主机等级的后续运行比较，不是生产容量承诺。

## 将来的替换边界

触发扩展后，仍保持模块化单体，不直接拆 Agent 微服务。优先在现有接口后替换三个 adapter：

1. `AgentAdmissionGate` 与 `AgentCostGuard`：使用支持原子配额和带期限计数的共享账本；
2. `AgentResponseReplayCache`：使用带 TTL、用户隔离、请求指纹冲突检查的共享幂等存储；
3. `AgentMetrics`：发送无用户、无内容、低基数的集中指标。

共享实现必须证明原子性、过期、取消释放、故障回退、数据最小化和成本上限；不得把 Prompt、回答、API Key 或用户身份写入共享状态。

## 回滚

保持 `AI_NAV_API_WORKERS=1` 和 `process_local` 即可回到当前拓扑，不涉及数据库迁移。真实 Provider 仍可通过独立实时开关关闭。
