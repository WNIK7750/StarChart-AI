# 助手空会话欢迎区与本地一键启动恢复设计

> 日期：2026-07-30
> 状态：用户已批准方案 A，待实现
> 范围：助手空会话展示、仓库根目录 `start.ps1` 本地启动可靠性

## 1. 目标

修复两个可独立验收的问题：

1. 游客或登录用户每次新建空对话，以及恢复任何空对话时，都显示
   “今天想学什么？”、说明文案和四个建议问题；已有消息的对话继续只显示消息，
   不重复插入欢迎区。
2. 根目录 `start.ps1` 能识别损坏的项目虚拟环境并自动重建；依赖安装、运行时
   解析、端口占用或应用启动失败时给出明确阶段和错误，并避免双击启动后窗口无提示
   关闭。

本任务只改本地开发启动流程，不把 `start.ps1` 描述为 HTTP 测试服务器或生产部署
工具。HTTP 测试仍按既有不可变发布和 runbook 执行。

## 2. 已确认根因

### 2.1 空游客会话

`renderGuestConversation()` 找到刚创建的游客会话后会清空消息容器，再遍历空消息
数组，因此不会调用已有的 `resetConversation()`。登录会话创建和空会话恢复已经
存在欢迎区重置路径，游客新建路径与其不一致。

### 2.2 `start.ps1` 异常退出

当前脚本只用目录是否存在判断 `.venv` 是否可用。实际 `.venv` 中的 `python.exe`
和 `pip.exe` 已无法创建进程，错误路径中的中文显示为 `????`。脚本仍继续执行，
既不检查外部命令退出码，也不捕获错误或保留窗口。

本机 `python` 和 `py` 当前不在 `PATH`，但 `.venv/pyvenv.cfg` 记录的基础 Python
解释器有效。使用该解释器在当前中文仓库路径重新创建临时虚拟环境后，新的虚拟环境
Python 可正常运行，证明自动重建是可行的最小恢复路径。

## 3. 设计

### 3.1 统一空会话欢迎区

继续复用 `frontend/assistant.html` 中唯一的 `#welcome` 模板和
`resetConversation()`，不复制第二份欢迎区 DOM。

`renderGuestConversation()` 的渲染规则为：

- 没有游客会话：显示欢迎区；
- 找到游客会话但消息数为 0：显示欢迎区并选中该会话；
- 有消息：清空欢迎区并按顺序渲染消息。

登录新建会话与登录空会话恢复保持现有规则，并增加契约测试，确保所有空会话入口都
继续调用同一重置函数。建议按钮仍使用现有四个 `data-prompt`，不改变 Agent 请求、
游客记忆或登录会话数据结构。

### 3.2 自恢复本地启动器

`start.ps1` 分为四个清晰阶段：

1. **解析基础 Python**：优先使用显式 `AI_NAV_PYTHON`，其次读取
   `.venv/pyvenv.cfg` 的 `executable`，最后尝试 `python` 和 `py`。每个候选都必须
   实际运行 `import sys`，不能只检查文件存在。
2. **保证项目虚拟环境健康**：实际运行 `.venv/Scripts/python.exe -c "import
   sys"`。失败时只删除仓库根目录下精确的 `.venv`，再用已验证的基础 Python
   重建；不得删除其他目录。
3. **安装并校验依赖**：固定使用健康虚拟环境的 `python -m pip install -r
   backend/requirements.txt`，检查退出码；不再直接调用可能嵌入失效路径的
   `pip.exe`。
4. **启动或复用应用**：先检查 `127.0.0.1:8088`。若健康端点确认是当前应用，
   明确提示已经运行并给出规范首页地址；若端口被非目标服务占用，明确失败。端口空闲
   时以前台方式运行 `backend/run.py`。

脚本用 `$ErrorActionPreference = "Stop"` 和显式退出码检查统一失败处理。交互式
双击运行遇错时显示阶段、可操作提示并等待确认；自动化调用可传 `-NoPause`，返回
非零退出码而不等待输入。

脚本不打印 `.env`、Token、Cookie、数据库内容或 Provider 请求；不默认打开真实
Provider，不停止或重启未知进程。

## 4. 错误处理

- 找不到任何可用基础 Python：提示设置 `AI_NAV_PYTHON` 或安装受支持 Python。
- `.venv` 不健康且重建失败：报告“虚拟环境重建”阶段并保留原始错误摘要。
- 依赖安装失败：报告“依赖安装”阶段，不继续启动应用。
- 8088 健康端点返回当前应用：视为启动已满足，不创建第二个实例。
- 8088 被其他服务占用或健康检查不匹配：拒绝覆盖、拒绝终止进程并提示释放端口。
- 应用进程异常退出：保留其非零退出码；交互模式等待用户确认后关闭。

## 5. 测试与验收

### 5.1 自动化

- Agent 前端契约测试覆盖游客空会话必须调用 `resetConversation()`，并保留现有
  “今天想学什么？”与四个建议问题。
- 新增启动器契约测试，检查：
  - 实际运行虚拟环境健康探针；
  - 损坏环境只允许重建精确 `.venv`；
  - 使用 `python -m pip`；
  - 检查外部命令退出码；
  - 识别 8088 已有健康实例；
  - `-NoPause` 与交互错误保留路径均存在；
  - 不包含凭据、真实 Provider 或仓库外 Git 操作。
- 运行前端专项、Node 全集、PowerShell 语法解析、`git diff --check` 和与启动器
  相关的快速 Python 导入检查。

### 5.2 浏览器

在 `http://127.0.0.1:8088/assistant` 验证桌面端和移动端：

1. 初次进入显示欢迎区；
2. 连续新建两个游客会话，每个空会话都显示欢迎区；
3. 发送消息后欢迎区消失；
4. 重新打开空会话，欢迎区恢复；
5. 页面无框架错误覆盖层、无相关控制台错误、无横向溢出。

登录态至少验证新建短期会话与恢复空短期会话继续显示欢迎区，不改变长期会话与用户
数据边界。

### 5.3 启动器

使用合成环境变量且禁用真实 `.env`：

1. 健康 `.venv` 路径可启动；
2. 损坏 `.venv` 能自动重建；
3. 依赖失败返回非零并给出阶段；
4. 8088 已有本应用时不启动第二个实例；
5. 非交互 `-NoPause` 不等待输入。

测试产生的数据库、上传目录、日志和截图必须位于仓库外临时目录；不得进入 Git。
