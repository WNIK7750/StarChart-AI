# Agent 到发布收口执行路线

更新时间：2026-07-15

## 1. 路线目标

在保持模块化单体和现有领域边界的前提下，把确定性只读 Agent 推进为可用、可替换、可观测、可回滚的站内智能助手，并完成发布前的跨浏览器、内容、安全、迁移和运行演练。

执行顺序固定为：

```text
基线确认
  -> 真实模型只读最小闭环
  -> 流式会话
  -> 经确认的用户闭环
  -> 质量与运行治理
  -> 前端完整体验与兼容性
  -> 发布收口
```

除修复阻塞问题外，不跨阶段并行堆叠后续能力。每个阶段以用户可见结果和门禁为完成单位。

状态约定：`[x]` 已完成，`[ ]` 未开始或待完成。

## 2. Phase 0：交接与基线

目标：确认后续开发建立在已验收事实上。

- [x] 非 Agent Foundation 总门禁通过并归档。
- [x] 确定性 Agent 结构化 chat、站内引用和工作流草案可运行。
- [x] 工作流保存具备确认、授权、幂等和审计闭环。
- [x] Learning、Tools、Users Context 通过公开能力接入 Agent。
- [x] 建立 Agent 专项验证入口 `scripts/verify-agent.ps1`。
- [x] 形成开发交接、执行路线和后续任务启动提示。

门禁：`verify-foundation.ps1` 与 `verify-agent.ps1` 同时通过，Agent 失败不影响普通 Learning/Tools 页面。

## 3. Phase 1：真实模型只读最小闭环

目标：用户提出一个站内问题，真实模型仅根据 Learning/Tools/Users 最小上下文回答，并返回可验证的卡片和引用；模型不可用时确定性模式仍可工作。

### 交付任务

- [ ] 定义项目自有的 Provider 请求、结果和错误模型，仅隔离真实外部 SDK 边界。
- [ ] 接入一个真实 Provider，实现配置校验、超时、有限重试、取消和敏感信息保护。
- [ ] 将“检索事实 -> 模型组织回答 -> 输出守卫”接入现有 Agent 用例，不改变领域服务。
- [ ] 保持现有 `AgentStructuredResponse` 为前端稳定契约，新增字段采用兼容演进。
- [ ] 增加 deterministic/model 模式标识、明确回退原因和 request ID 关联。
- [ ] 建立首批 QA、导航、工具推荐、学习计划、空结果、注入和越权评估样例。
- [ ] 使用 fake provider 完成单元和契约测试，再用真实 Provider 完成受控集成验证。

### 完成门禁

- 至少覆盖计划书中的四类核心用户问题，引用均来自当前站内事实。
- Provider 未配置、超时、限流、无效结构和输出校验失败均有可解释回退。
- 替换 fake/real/deterministic 实现不修改 Learning、Tools、Users、HTTP schema 或前端渲染代码。
- 模型不能自由生成站内链接、工具标识或未授权用户数据。

## 4. Phase 2：流式输出与会话连续性

目标：在同一套编排逻辑上增加可取消的流式体验和可继续的短期会话，不引入长期记忆。

### 交付任务

- [ ] 定义统一 Agent 事件模型，使 JSON 完整响应和 SSE 共用同一编排结果。
- [ ] 增加流式接口、前端增量渲染、取消、超时和断线后的可恢复状态。
- [ ] 通过追加迁移建立最小会话与消息持久化，明确用户隔离、分页和删除规则。
- [ ] 上下文构建只读取当前会话窗口；达到预算时使用可验证摘要或截断策略。
- [ ] 增加会话读取/继续能力，避免页面刷新后丢失已持久化对话。
- [ ] 为流式和会话能力增加独立 Feature Flag，关闭后回到 Phase 1 的完整响应。

### 完成门禁

- 完整响应与流式最终结构语义一致，不存在两套回答规则。
- 用户只能访问自己的会话；删除、隐私导出和账号删除生命周期已覆盖。
- 客户端取消不会继续写消息，断线和 Provider 错误不会留下“完成”假状态。
- 关闭 Feature Flag 不需要数据回滚，确定性 Agent 仍可用。

## 5. Phase 3：经确认的用户闭环

目标：Agent 不只给建议，还能在明确确认后把有价值结果保存到 Users 所有的状态或资产中。

### 交付任务

- [ ] 先完善现有工作流草案的修改、预览、确认和保存体验，保持 Users Assets 为唯一写入者。
- [ ] 根据真实产品场景选择最多一类新增写能力，例如收藏或学习计划保存；不一次开放全部命令。
- [ ] 为每个写命令定义确认文案、权限、幂等键、目标用户、审计事件和失败恢复。
- [ ] 让 Agent 在生成前读取用户允许的偏好、进度和资产摘要，不读取不必要的隐私字段。
- [ ] 长期记忆保持关闭；只有用户同意、删除/导出和质量评估同时完成后再纳入本阶段。
- [ ] 覆盖重复提交、并发冲突、权限撤销、资源归档和 Provider 重试不重复写入。

### 完成门禁

- 所有写操作都由用户确认触发，模型输出本身不构成命令。
- Agent 只能调用 Users command facade，不直接写表或重用前端提交绕过权限。
- 重试和并发不会生成重复资产或错误进度，失败有可恢复反馈。
- 用户关闭 Agent 或撤回记忆同意后，普通用户资产和学习体验仍正常。

## 6. Phase 4：质量、评估与运行治理

目标：用数据证明 Agent 的回答、推荐和写入安全可接受，并能定位一次失败发生在哪个边界。

### 交付任务

- [ ] 建立版本化评估集：QA、导航、工具推荐、学习计划、工作流、安全、注入和越权。
- [ ] 定义发布阈值和守护指标：引用真实性、链接有效率、约束满足率、结构校验率、延迟和成本。
- [ ] 记录最小 trace：request ID、模式、Provider、prompt 版本、调用工具、结果数量、耗时、回退和校验错误。
- [ ] 对日志和评估输入执行隐私脱敏，不记录 token、密码、密保答案或完整敏感用户数据。
- [ ] 建立 Provider、stream、session、write、memory 能力开关和回滚说明。
- [ ] 用评估结果决定是否需要向量检索、状态图或第二 Provider；没有证据则维持简单实现。

### 完成门禁

- 评估可以在本地和 CI 重复执行，固定样例结果可比较。
- 关键指标达到项目设定阈值，安全和越权样例零放行。
- 一次请求可以通过 request ID 关联 API、Provider、工具调用和最终校验结果。
- 任一新增复杂组件都有触发证据、关闭开关和降级路径。

## 7. Phase 5：前端体验与兼容性收口

目标：把已经验证的 Agent 能力做成稳定、可访问、可恢复的产品体验，而不是只完成后端接口。

### 交付任务

- [ ] 完善独立 Agent 页的会话列表、流式状态、停止、重试、引用、工作流确认和错误恢复。
- [ ] 评估页面内上下文入口；首批只选一个高价值页面接入，不同时建设全站悬浮入口。
- [ ] 保持 Agent UI 组件按回答、引用、步骤、确认等真实复用点组织，避免组件层级过深。
- [ ] 覆盖键盘、焦点、读屏状态、reduced motion、长文本、空结果和窄屏布局。
- [ ] 使用 Opera Browser Connector 做真实页面读取和截图，使用自动化覆盖交互、控制台和多视口矩阵。
- [ ] 补充 Firefox、WebKit 和真实移动设备的关键 Agent 流程。
- [ ] 修改涉及的大型页面时迁移对应内联 CSS，不发动与 Agent 无关的全站 CSS 重构。

### 完成门禁

- 登录、提问、流式/完整回答、引用跳转、取消、重试、会话继续和确认保存全部可操作。
- 桌面、平板和移动端无水平溢出、遮挡、失焦或不可恢复状态。
- Chromium、Firefox、WebKit、Opera 和至少一种真实移动设备关键路径通过。
- Agent 页面失败不影响主导航、Learning、Tools 和 Users 页面。

## 8. Phase 6：发布收口

目标：完成一次可部署、可回滚、有证据的发布候选验收。

### 交付任务

- [ ] 冻结本次发布的 Agent API、事件、迁移、Prompt 和评估集版本。
- [ ] 执行 Agent、Foundation、迁移、备份恢复、安全、性能和浏览器总门禁。
- [ ] 重新在线巡检 Learning/Tools 公开链接，显式写回并复核 Agent 使用的引用。
- [ ] 验证生产配置：密钥、CORS、Cookie、Provider 凭据、超时、限流、日志脱敏和 Feature Flag 默认值。
- [ ] 演练 Provider 故障、Agent 总开关关闭、流式关闭、写能力关闭和数据库恢复。
- [ ] 形成发布说明、已知限制、回滚步骤和最终验收报告。

### 完成门禁

- `verify-foundation.ps1`、`verify-agent.ps1` 和新增发布门禁全部通过。
- 新迁移 checksum 一致，备份恢复完整性和外键检查通过。
- Agent 在 Provider 故障时可明确降级或关闭，普通网站功能不受影响。
- 公开链接无 unavailable；degraded 有原因、影响判断和后续复检安排。
- 没有未解释控制台错误、高优先级安全缺陷或阻塞型浏览器问题。

## 9. 非 Agent 维护项的安排

- degraded 外链：开发阶段仅处理 Agent 首批必需资源；Phase 6 全量复检。
- Firefox/WebKit/真实移动设备：不阻塞 Phase 1-4，Phase 5 必须完成。
- 大型页面内联 CSS：按触及范围渐进整理，不作为独立前置项目。

## 10. 阶段完成记录模板

每完成一个 Phase，在其任务前更新 `[x]`，并在文档末尾追加一条简短记录：

```text
日期 / Phase：

```

不要把“创建接口、目录或抽象”单独视为阶段完成。
